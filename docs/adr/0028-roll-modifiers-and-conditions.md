# ADR 0028 — Roll modifiers and conditions

**Status:** Accepted (rpg-42a.90). **Decision:** A RulePack declares its roll modifiers, conditions and difficulty ladder as plain data. Proposals name modifiers by id. The engine validates them, computes the total and records every applied modifier on the roll event. Conditions are campaign events that the engine folds into later rolls.

**Context:** Checks used the attribute bonus and a fixed DC. Cover, darkness, wounds, advantage and lasting conditions came only from narration, which ADR 0026 forbids for mechanics.

**Decision details:**
- Vocabulary (`packages/rules/src/modifiers.ts`): `modifiers` are `{ id, label, effect }`, where `effect` is `flat` (adds to the total), `dice` (adds or removes dice from a pool) or `keep` (`highest` or `lowest` of two d20, for advantage and disadvantage). `conditions` are `{ id, label, modifiers[], appliesTo?, duration }` with a duration of `turns` or `scenes`. `difficulties` map a name to a DC. Effects are data only; nothing is evaluated. Names and numbers live in the pack (`D20_LITE_VOCABULARY`, `DICE_POOL_LITE_VOCABULARY`); core types carry no D&D field. Advantage and disadvantage cancel. A vocabulary also lists the effect kinds its checks can apply (`effects`: d20-lite `flat` and `keep`, dice-pool-lite `dice`); a modifier with another kind is refused, and a condition modifier of another kind is skipped at roll time.
- Request: `{ id, reason, sourceRule?, value? }`. In `as-written` only ids the effective RulePack declares are accepted and any other id refuses the proposal. In `relaxed` any labelled modifier is accepted if it has a reason and an integer `value` within ±10 (`MAX_MODIFIER_VALUE`). At most 6 modifiers per roll. A relaxed modifier is always flat. This is the path for GM-only mode (rpg-42a.82): the GM cites the imported rule section in `sourceRule`.
- Applied modifiers are stored with their effect (`AppliedModifier`) on the `CheckOffered` offer, the `CheckResolved` resolution and the `GmRolled` resolution. The resolution also stores `bonus` (attribute plus flat modifiers, as before), `attribute`, `target` and `keep`. All new fields are optional, so events recorded before this change replay unchanged. A roll with `keep` stores both dice; the kept die is derived from the stored draws.
- Proposals: `check` and `gm-roll` carry `modifiers`; `check` also carries `difficulty`. New `condition` and `condition-end` proposals apply and end a condition on the player character. A `gm-roll` takes flat modifiers only, which add to the expression modifier.
- Conditions: `ConditionApplied` stores the resolved modifiers, the duration and the optional `appliesTo` rule list, so the event is self-contained. In as-written the GM picks only the condition id; the pack's duration, `appliesTo` and label are used. `ConditionRemoved` ends it early. `activeConditionsOf(events, actorId, ruleId)` folds the event log: a `turns` duration counts play turns after the apply event (system turns, such as GM proposals and sheet edits, carry `system: true` on `PlayerActionSubmitted` and are skipped); a `scenes` duration counts `SceneOpened` events. The roll builder adds the active conditions' modifiers to the next matching roll and skips a condition modifier whose id the proposal already set. The fold is pure, so replay equals live state.
- Context: when the campaign has dice, the GM packet lists the pack's modifier ids with their effects, the known conditions with durations and the difficulty names (`modifiersPrompt`). The prompt tells the GM never to state numbers in prose.
- Roll card: the visualization result carries `breakdown` (`attribute`, `modifiers[]`, `target`, `kept`). The desktop card and the TUI roll line list the die, the attribute, each modifier with its reason and the total against the target. Strings are in the en, es (desktop) and pt-BR catalogs.

**Consequences:**
- A dice-step effect (change the die size) and a dice-pool bonus other than extra or fewer dice are not modelled. Add an effect kind when a pack needs one.
- Conditions target the player character. NPCs have no sheet, so an NPC roll takes only explicit flat modifiers.
- A refused modifier drops the whole check or gm-roll proposal silently, as ADR 0026 and ADR 0027 do for other refusals.
- Vocabulary data is typed TypeScript for the built-in packs. Imported RulePacks have no vocabulary yet and use the relaxed path.

**Amendment (rpg-42a.103):**
- Dice step: `ModifierEffect` gains `{ kind: 'step', steps }`, an integer within ±10 (`MAX_MODIFIER_VALUE`). `summarizeModifiers` adds a `step` total. `steppedSides` moves a die size along 4, 6, 8, 10, 12, 20 and stops at both ends; a size off the ladder is unchanged. d20-lite declares `weakened` (-1) and `empowered` (+1) and lists `step` in `effects`; the attack damage die uses the total. Dice-pool-lite and `gm-roll` do not list `step`, so the existing "effect these checks cannot apply" refusal covers them. The roll card shows a step as "N die step" in the en, es and pt-BR catalogs.
- Imported vocabulary: `ModifierPolicy` takes an optional `cites(rule)`. `resolveModifiers` refuses a modifier whose `sourceRule` fails it and keeps the citation optional. In GM-only mode `cites` matches the section titles of the imported files (same check as the `gm-roll` section, ADR 0031). Imported text stays data. A step applies only to an attack against a target sheet; on any other d20-lite check it is dropped at roll time, as a condition modifier of another kind is. In relaxed GM-only mode the `gm-roll` expression holds the base dice only and bonuses go in `modifiers` with a `sourceRule`, so the flat total is not counted twice. In as-written GM-only mode no modifier id is accepted, so the expression includes the bonus the rules name, as before. Conditions in relaxed GM-only mode are recorded state only; `rollForGm` does not merge them into later rolls. GM-only mode now has a policy with no vocabulary, so relaxed flat modifiers work there; as-written still refuses any modifier id.
